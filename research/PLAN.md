# 残タスク・機能追加案 調査計画（6 ラウンド）

目的: 未知の残タスク・機能追加案をエージェントチームで洗い出し、5 回の調査
（ラウンド 1〜5）の後に第 6 ラウンドで重複排除・妥当性評価・吸収を行う。

## ラウンド割当て

| Round | 観点 | 狙い |
| --- | --- | --- |
| 1 | リポジトリ内部監査 | コード / テスト / ドキュメント・CI / 先送り項目の棚卸し（複数エージェント並列） |
| 2 | 外部・上流調査 | DSH 本体の新機能・プラグイン生態系・公式 API の未活用部分 |
| 3 | ユーザーシナリオ / UX | 導入・設定・プロファイル間移行・運用摩擦 |
| 4 | 敵対的レビュー | セキュリティ / ロバストネス / 並行処理 / バージョン互換 |
| 5 | 実現可能性と優先度 | 候補の工数・リスク・依存関係を深掘り |
| 6 | 収束 | 重複統合・妥当性判定・最終レポートへ吸収 |

## ルール

- 各ラウンドの結果は `research/round-NN.md` に出典（ファイル:行 / URL）付きで記録する。
- 第 6 ラウンドで全候補を一覧化し、重複・矛盾・誤検知を整理して最終レポートを作成する。
- 調査は読み取り専用。コード変更は行わない（ユーザー依頼は「調査」まで）。
- エージェントの出力は仮説として扱い、親エージェントが Runtime Proof で事実確認する。
